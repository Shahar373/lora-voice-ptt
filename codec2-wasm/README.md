# Codec2 → WebAssembly

`build.sh` compiles the speech-codec part of [drowe67/codec2](https://github.com/drowe67/codec2)
plus `wrapper.c` into `src/codec/wasm/codec2.{mjs,wasm}`. The output is **committed**, so
neither local dev nor the Pages CI job needs Emscripten. Rebuild only when changing the
wrapper or the Codec2 version:

```bash
source /path/to/emsdk/emsdk_env.sh   # Emscripten (tested with 7.0.0)
npm run build:codec2
npm test                              # codec tests run the committed .wasm in Node
```

## Why a pinned, pre-1.2 commit

`CODEC2_MODE_450` was **removed upstream** in commit `6549fa1` ("rm-ed 450 & 450WB",
2023-07-16), before tag 1.2.0. Current `main` only has 700C as its lowest-rate mode.
We build from that commit's parent, `9f5e2de`, which still has both **450** and **700C**.

Checked when this was set up:

* 450: 18 bits / 40 ms frame (450 bit/s); 700C: 28 bits / 40 ms frame (700 bit/s).
* On Codec2's `hts1a` sample, the WASM encoder produces **bit-identical** frames to a native
  `c2enc` build for both modes. Decoded 450 audio matches native within ±3 LSB; 700C
  differs only in synthesized phase (float/libm differences), with frame energies matching
  to 0.56 dB on average.

If 450 turns out unintelligible in practice, the app falls back to 700C (mode id 1 on the
wire), which costs ~1.6× the airtime.

## What's included

Only the speech codec sources are compiled (no FreeDV modems), with the codebooks
generated by Codec2's own `generate_codebook` tool. Exports:
`c2w_create(mode)`, `c2w_encode`, `c2w_decode`, `c2w_bits_per_frame`,
`c2w_bytes_per_frame`, `c2w_samples_per_frame`, `c2w_destroy`.
